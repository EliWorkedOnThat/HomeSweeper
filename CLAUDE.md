# CLAUDE.md

Guidance for Claude Code sessions working on HomeSweeper.

## What this project is
HomeSweeper scrapes Albanian real-estate listing sites, stores the listings in SQLite and exports them to Excel. It is being built into a **product sold to real estate agents who are not technical**: a double-click desktop app (a local FastAPI server plus a plain HTML/CSS/JS UI in their normal browser) that updates itself whenever a new version is released. Keep it simple for them: no Python, no console, no extra servers, no Node/build steps. How the finished product is built and shipped is in [Product architecture](#product-architecture-target-for-the-finished-app). Follow it for any packaging, path, settings or update work.

**`NOTES.md` is the source of truth for the plan, the DB schema and the known gotchas.** Read it before any non-trivial change, and update it (including the `_Last updated_` date) when you change behaviour or finish a plan step.

## Run
The code must run on **Windows, Linux and macOS**. Linux is a dev platform only; shipped builds are Windows and macOS (see below). Use `pathlib` paths and no OS-specific launchers (no `.bat`/`.sh`). During development everything is started from a console.

Run from the project root. The imports are package-style (`Scraper.`, `MerrJep_al.`, `Duashpi_al.`, `Tools.`), so running a file directly breaks them. Site folders use underscores, never hyphens or dots (`Duashpi-al` can't be imported). Use `python3` on Linux/macOS and `py -3.14` on Windows:

    python3 -m Scraper.Engine                       # one turn (every site) in the terminal
    python3 -m Scraper.Server                       # web UI at http://127.0.0.1:8000 (or the next free port), Ctrl+C to stop
    python3 -m GazetaCelesi.PlaywrightScraper       # one Gazeta Celesi turn on its own, prints the listings (no DB)
    python3 -m Duashpi_al.PlaywrightScraper2        # one Duashpi turn on its own, prints the listings (no DB)
    python3 -m njoftime_al.PlaywrightScraper3       # one Njoftime turn on its own, prints the listings (no DB)
    python3 -m Tools.FetchHTML <url>                # save a page's HTML to Tools/HTML/ (--fast = plain HTTP, --show = visible browser)
    python3 -m Tools.AIEval                         # check the AI's filters on 39 sample questions (needs the API key, costs money)

Deps are pinned in `requirements.txt` (`playwright`, `fastapi`/`starlette`/`pydantic`, `uvicorn`, `anthropic`, `openpyxl`, `rich`, `httpx`, and `tzdata` on Windows); install them with `pip install -r requirements.txt`, then `playwright install chromium`. Add a line there for every new third-party import. Python 3.10+ (developed on 3.14). There is no test suite yet. **Setup for a fresh clone or after pulling someone's commits:** see "Running the project" in `NOTES.md`.

## Layout
- `Scraper/Engine.py` is the orchestrator. `main(skip_agencies=False, should_stop=None)` runs **one turn**: it connects to the DB, then for each `(site, scrape)` in `SCRAPERS` (MerrJep, then Gazeta Celesi, then Duashpi, then Njoftime) it loads `get_known_upids(site)`, calls the scraper, saves its listings with `save_listing()` and exports them to Excel, before moving to the next site. A crash in one site is logged and doesn't stop the next. If `should_stop()` turns True (pause), the remaining sites are skipped. It returns `{found, saved, failed, sites: {site: {...}}, paused, seconds}`, or `None` if the DB can't be opened. `seconds` is the turn's duration, timed by `Tools/Performance.py` (started before the first site, stopped in the `finally`, so paused and crashed turns are timed too). To add a site, write its scraper and add one line to `SCRAPERS`.
- `Scraper/DB.py` is the **only** file that touches SQLite: `connect_to_db()` (WAL on), `create_tables()`, `save_listing(connection, listing, site)` (an upsert on `(site, upid)`), `get_known_upids(connection, site)` (a set of saved UPIDs, so scrapers skip them), `get_listings(connection, site=None)` (dicts with `images`/`attributes` decoded from JSON).
- `Scraper/Output.py` has two functions. `save_listings(listings, site)` appends to `Output/listings.xlsx` and is used by the engine. `build_workbook(listings)` returns fresh `.xlsx` bytes from DB rows and is used by the UI's export download. Columns are listed by database name in `BASE_COLUMNS`; their Albanian headers live in `HEADERS`, so a new column needs an entry in both.
- `Scraper/Server.py` is the FastAPI server, kept as a thin layer with no scraping logic. Its endpoints are `GET /api/listings`, `GET /api/scrape/status` (the running/last turn, plus continuous mode: next turn, turn count and new listings this session), `POST /api/auto/start` (play: `{interval_minutes}` from `AUTO_INTERVALS`, the break between turns) and `POST /api/auto/stop` (pause: sets `PAUSE_EVENT`, so a running turn stops early and saves what it has), `POST /api/preferences` (`{skip_agencies}`, the "Jo Listime Agjensie" dropdown, snapshotted when each scrape starts and passed to `Engine.main(skip_agencies=...)`), `POST /api/schedule` (the daily start, saved in `Data/settings.json`), `GET/POST/DELETE /api/blocked` (blocked sellers, left out of every result by `without_blocked()`), `POST /api/favourite` (`{listing_id, favourite}`, the heart on a card; updates that listing in the listings cache with `set_cached_favourite()` instead of rebuilding it), `GET /api/favourites` (only the hearted listings, minus blocked sellers, read straight from the DB with `get_listings(favourites_only=True)`; the favourites page uses it instead of downloading every listing), and `GET /api/export`. It serves `UI/` at `/` and binds to `127.0.0.1` only, on port 8000 or the next free one (`Scraper/Instance.py`). It only accepts the Host `127.0.0.1`/`localhost`, and every POST/DELETE must carry our own `Origin` (anti DNS-rebinding/CSRF, see "Server safety" in `NOTES.md`); it sends a strict CSP, so the UI must never use inline scripts or styles. Every turn starts through `start_scrape()`, which holds `SCRAPE_LOCK`, and `auto_loop()` (a background thread that wakes on `AUTO_WAKE`) is its only caller. Never start a scrape any other way, and `STATE_LOCK` guards the shared status dicts.
- `UI/` (`index.html`, `style.css`, `app.js`, plus `favourites.html` + `favourites.js` for the favourites page at `/favourites`) is plain HTML/CSS/JS with no build step. `favourites.html` loads `app.js` to reuse its cards; `<body data-page="favourites">` makes `app.js` skip `startDashboard()`, so dashboard-only wiring must go inside that function. The dashboard loads every listing once, then filters and sorts in the browser, and polls the status every 3 s during a scrape. The favourites page loads only the favourites (`/api/favourites`). The filters are multi-select dropdowns (`FACETS`) and two-thumb range sliders (`RANGES`) built by `app.js`. `enrich()` derives their values (property type, merged condition, furnishing, features, floor, bathrooms, price in EUR, €/m²) from the columns and the raw `attributes`. See "UI filters" in `NOTES.md`. Listings are shown as a flexbox grid of cards that display every scraped field. Every flex child has `min-width: 0`, so nothing overflows its box. Text is clamped, and `markOverflow()` makes any cut-off box clickable; it opens the full content in a shared `<dialog>` preview. The same dialog is used for the photo gallery and the "All details" view. It builds DOM nodes with `textContent`, never `innerHTML`, because the data is scraped.
- **Pyet AI:** `Scraper/AI.py` sends a question to Claude, which returns a `Search.Filters` object (structured output, never SQL, never sees listings). `Scraper/Search.py` runs those filters in Python, including keyword groups over title/description/address/tags, and ranks by soft `preferences` (vague wishes) and price/size targets, and returns near misses (one requirement off) when little is found. `Scraper/Derive.py` derives the shared filter values (property type, merged condition, furnishing, features, floor (also read from the text), bathrooms, posting date, price in EUR) used by both the AI search and the dashboard (`/api/listings` sends them under `derived`). History lives in the `ai_searches` table and shows as a sidebar on the AI page; each search has its own URL `#/ai/<id>`. API key: `ANTHROPIC_API_KEY` or the git-ignored `Data/anthropic_api_key.txt`; never commit it. Details in "Pyet AI" in `NOTES.md`.
- `Tools/` holds dev utilities. `AIEval.py` checks the AI against 39 agent-style questions (real API, costs money). `FetchHTML.py` saves a URL's HTML to `Tools/HTML/` (git-ignored) so a site's markup can be studied before writing its scraper. It uses Playwright by default and HTTPX with `--fast`. `Performance.py` is the turn timer (`start_timer()`, `stop_timer()`, `run_time(start, end)`); the Engine imports it, so it has to be bundled (or moved into `Scraper/`) when packaging.
- `Scraper/Console.py` has `utf8_output()`, called first in every entry point (a cp1252 console crashed on emoji in titles).
- `Scraper/Instance.py` allows one run per PC and picks the server's port; the `__main__` of `Server.py` and `Engine.py` use it. `acquire_lock()` takes an OS lock on `Data/server.lock` (`msvcrt` on Windows, `fcntl` on macOS/Linux; the OS drops it when the process dies, even after a crash). If it's already held, `refuse_second_run()` names what's running (the address from `Data/server.json`) and exits with code 1, leaving the running one alone: two runs would scrape into the same DB. The server closes its socket and then releases the lock in a `finally`; `exit_cleanly_on_signals()` makes Ctrl+C, Ctrl+Break and `kill` reach that `finally` (uvicorn re-sends the signal after its graceful shutdown, which by default kills the process outright). `bind_free_port()` tries 8000 first, then up to 8049, and hands the bound socket to uvicorn. `port_taken()` test-binds the wildcard addresses (`0.0.0.0` and `::`, no listen, so no firewall prompt), because Windows lets a `127.0.0.1` bind succeed next to another program's `0.0.0.0` listener. See "One server per PC, free port" in `NOTES.md`.
- `REVIEW.md` is the 2026-11-06 team review: what was fixed and the ranked roadmap (pipeline, tests, CI, UI, scrapers, infrastructure).
- `Scraper/config.py` holds the developer settings: `Demo_Environment` (True means 5 new listings per site per turn), `Listings_Per_Turn` (50, used when demo is off), `Headless` (True means no browser window), `Window_Position`/`Window_Size` (where the visible window opens when `Headless` is False; off screen by default, `None` puts it back on screen for debugging), `Use_Installed_Chrome` (True = scrape with the PC's Google Chrome, falling back to Playwright's Chromium; False = always Playwright's Chromium), `Rest_Time` (s between listings on MerrJep and Duashpi, between pages on Gazeta and Duashpi), `Database_Name`. The break between turns is **not** in config; staff pick it in the UI.
- `MerrJep_al/PlaywrightScraper1.py` is the MerrJep scraper. `create_browser_instance(skip_agencies=False, known_upids=(), should_stop=None)` runs one turn and returns a list of listing dicts. For each new listing it scrolls to the card and pauses (`scan_card()`), Ctrl+clicks it into a new tab (`open_listing_tab()`), reads JSON-LD + HTML tags there, and closes the tab; the results tab never navigates (see "Listings open in a new tab" in `NOTES.md`). With `skip_agencies=True` it skips any results card containing `span.isstore` ("Agjent për shitje të pronës") before clicking. `ATTRIBUTE_COLUMNS` maps Albanian tag labels to the standard DB columns, with `parse_number()` and `combine_phones()` as helpers. The Engine imports it as `scrape_merrjep`.
- `MerrJep_al/Request1.py` is an HTTPX `fetch()` that nothing uses yet. It's parked on purpose (plain HTTP is easier for sites to spot), so leave its unused imports alone.
- `GazetaCelesi/PlaywrightScraper.py` is the Gazeta Celesi scraper. `scrape_gazetacelesi(skip_agencies=False, known_upids=(), should_stop=None)` has the same turn logic as MerrJep. It reads each results page's embedded Next.js JSON (`script#__NEXT_DATA__`), which holds the full data for all 20 listings, so it **never opens individual listings**. It still scrolls to each new card and pauses (`scan_card()`) so the visit looks human. Details and the field mapping are in `NOTES.md`. `GazetaCelesi/Request.py` is an empty placeholder.
- `Duashpi_al/PlaywrightScraper2.py` is the Duashpi scraper. `scrape_duashpi_al(skip_agencies=False, known_upids=(), should_stop=None)` works like MerrJep (scroll and pause, then opens each new listing in a new tab). It closes the cookie popup first (`#acceptAllButton`, its backdrop blocks every click), ignores premium cards (not in date order, repeated across pages), reads the price from the page because the JSON-LD converts LEK to EUR, and detects agencies on the listing page only (a `LocalBusiness` seller JSON-LD or a licensed-agent box). New posts push cards onto the next page during a turn, which is why listings open in their own tab: our results tab never reloads, so its cards can't move. Details are in `NOTES.md`. `Duashpi_al/Request2.py` is an empty placeholder.
- `njoftime_al/PlaywrightScraper3.py` is the njoftime.com scraper (site key `njoftime`). njoftime is a XenForo forum, so `scrape_njoftime(skip_agencies=False, known_upids=(), should_stop=None)` walks **five forums** (`FORUMS`: homes, business premises and land, for sale and rent) and shares each turn's quota between them, with one resume page per forum (`RESUME_PAGES`). It opens each new thread in a new tab like Duashpi. Threads are sorted by the seller's last refresh, not by posting date, and a refresh resets the date too, so `published_date` is the last refresh. Agencies (company logo on the card or a business-sounding name) are skipped from the card without a click. The "Cmimi Euro" field is converted, so a LEK price in the title wins. Details are in `NOTES.md`.
- **All scrapers share one structure.** Module globals plus `reset_state()`; `turn_limit()`, `turn_full()`, `stop_requested()` and `turn_over()`; `page_url(n)`; `next_page()` (the jump to `RESUME_PAGE`); `clamp_resume_page()`; a copy of `launch_browser()`; the entry function wraps `run_turn()` and always returns what it collected; and an identical **error handling block** (`classify()`, `open_page()`, `listing_failed()`, `TurnStop`…, between the `Error handling` / `End of the error handling block` comments). Never call `page.goto` directly, use `open_page()`. Keep a new site's scraper in the same shape. See "Scraper error handling" in `NOTES.md`.
- `Data/Homesweeper.db` and `Output/` are generated and git-ignored.
- `Analyze.md` is a scratchpad for HTML samples and URLs.

## Rules / conventions
- **All SQL lives in `DB.py`.** Scrapers and the engine call its functions, so a later PostgreSQL switch only touches that file. Every write goes inside `with connection:`.
- **Scraper contract:** each site exposes `scrape(skip_agencies=False, known_upids=(), should_stop=None)`, which runs **one turn** and returns a list of dicts with the same keys (`upid, url, title, description, price, currency, phone, seller, published_date, published_time, listing_type, size_m2, rooms, condition, city, address, posted_by, images (list), attributes (dict)`).
  - **One turn:** at most `turn_limit()` new listings. Start at page 1 (newest), skip `known_upids` before doing any work on them, and return early with what it has when `should_stop()` is True.
  - **Saving:** the engine saves the results with the site key (`"merrjep"`, `"gazetacelesi"`).
  - **Field mapping:** each site maps its own labels to the shared English filter columns and keeps the raw tags in `attributes`.
  - **Wording:** write values in MerrJep's wording (`Shitet`, `Jepet me qera`, `Kompani`, `Tiranë`, `EUR`/`ALL`), so the UI dropdowns show one option per meaning.
- `CREATE TABLE IF NOT EXISTS` never alters an existing table. In dev, delete `Data/Homesweeper.db` after a schema change. Once real data exists, use `ALTER TABLE`.
- **All UI text is Albanian.** The product is sold to Albanian staff, so every label, button, placeholder, tooltip, `aria-label`, alert and message in `UI/` and every user-facing filename (e.g. the Excel export) is in Albanian. Code, comments, API field names and console logs stay in English. Numbers use Albanian style (`185.000`, `72,5`) and times are shown in Tirana time (`03.11.2026, 16:01`) via `formatNumber()`/`localTime()` in `app.js`, which are formatted by hand because browsers don't reliably ship `sq-AL` locale data.
- Keep the existing code style: `#Comment` headers above each function, `rich` coloured prints for logging, `Path(__file__)`-relative paths.
- Work on the `dev` branch. `main` is the PR target. Commit only when asked.

## Product architecture (target for the finished app)
Agreed on 2026-11-04. Nothing below is built yet; the step-by-step plan is Phase 4 in `NOTES.md`. If a change would contradict this section, discuss it first and update this section rather than drifting from it.

### Decisions
| Topic | Decision | Why |
|---|---|---|
| Users | Non-technical real estate agents, **almost all on Windows**. macOS must work too. | Windows is the main target and gets tested first. macOS is a supported platform, not an afterthought. |
| Data | **Each agent has their own separate data** in a local SQLite file. There is no shared or central DB. | One file per PC and no server to run. Never add a feature that needs a central database. |
| UI | Opens in the agent's **normal browser**, with a **system tray / menu-bar icon** (`pystray`) to reopen or quit. | No pywebview: browsers are on every PC and behave the same everywhere. |
| Licensing | **Sold without licence keys.** No activation, no telemetry. | Nothing phones home except the update check. |
| Source code | Stays in the **private** repo. | Builds are published from a separate **public releases repo** (see Updates). |
| Platforms shipped | Windows (x64) and macOS (Apple Silicon and Intel, as one universal build or two builds). | Linux builds are not shipped, but the code stays cross-platform. |

### Packaging
- **PyInstaller, `--onedir`, windowed (no console).** `--onefile` is not used: it starts slowly because it unpacks on every launch, and it triggers more antivirus false positives. PyInstaller can't cross-compile, so each OS is built on its own CI runner (see the release flow).
- **Windows:** an **Inno Setup** installer that installs **per user** to `%LOCALAPPDATA%\Programs\HomeSweeper`, with no admin rights needed. Per-user is required so the updater can replace the files without a UAC prompt. The installer adds a Start menu shortcut, an optional desktop shortcut and an uninstaller.
- **macOS:** a `HomeSweeper.app` inside a `.dmg` (drag to Applications).
- **Chromium is not bundled.** On first launch the app runs Playwright's driver to download Chromium into the user data folder (`PLAYWRIGHT_BROWSERS_PATH` = `<data>/browsers`). While it downloads, the browser shows an Albanian "Duke përgatitur…" page. When an update bumps the Playwright version, the matching Chromium is downloaded the same way. **Changed 2026-11-12:** the scrapers prefer the agent's installed **Google Chrome** (`start_browser()`, `channel="chrome"`), because real users send `"Google Chrome"` in their `Sec-CH-UA` header and Playwright's Chromium only sends `"Chromium"`. Chrome gets a fresh, empty profile each launch, never the agent's own. If Chrome isn't installed or doesn't start, they fall back to Playwright's Chromium, so that download is still needed. Chrome updates itself apart from Playwright, so after a Playwright upgrade, test against the current stable Chrome.
- In the shipped app, `Demo_Environment = False` and `Headless = True`, always.

### Where files live
The app folder is **replaced on every update**, so nothing the agent creates may be stored there.
- All paths come from **one module, `Scraper/Paths.py`** (to be created). Never build paths ad hoc elsewhere.
  - **App files** (`UI/` and other bundled resources): the project root in dev, `sys._MEIPASS` when frozen (`getattr(sys, "frozen", False)`).
  - **User data**: `platformdirs.user_data_dir("HomeSweeper")`, which is `%LOCALAPPDATA%\HomeSweeper` on Windows and `~/Library/Application Support/HomeSweeper` on macOS. In dev it stays the project's `Data/` and `Output/`, so nothing changes while testing.
  - Inside user data: `Homesweeper.db`, `exports/`, `settings.json`, `logs/`, `browsers/`, and `update/` (downloads in progress, plus the previous version for rollback).
- The current `Path(__file__)`-relative paths in `DB.py`, `Output.py` and `Server.py` move to `Paths.py`. That is the only allowed exception to the "`Path(__file__)`-relative paths" convention below.
- **Settings the agent changes** (the auto interval, "Jo Listime Agjensie", and later working hours) are saved to `settings.json` and survive restarts and updates. `config.py` stays for developer constants only.
- **DB schema changes must migrate**; never delete the file, because agents' DBs hold real data. Store a schema version in `PRAGMA user_version` and run ordered `ALTER TABLE` steps in `DB.py` from `create_tables()`. Back up the DB file to `update/` before migrating.

### Launcher
- The entry point `HomeSweeper.py` (to be created at the project root) is what PyInstaller freezes. It does four things:
  1. Sets up rotating logs in `<data>/logs/`. In a windowed PyInstaller build `sys.stdout` and `sys.stderr` are `None`, so `rich` printing would crash. Either redirect them to the log, or route all logging through a small wrapper that uses `rich` in dev and the log file when frozen.
  2. Enforces **one instance**: a lock file in user data holds the port. If the app is already running, a second launch just opens the browser to it and exits.
  3. Picks a **free port on `127.0.0.1`** (never `0.0.0.0`), starts uvicorn in a thread, and opens the default browser with `webbrowser.open`.
  - Steps 2 and 3 are already built in `Scraper/Instance.py` (used by `python -m Scraper.Server`); the launcher should call it, not redo it. Today a second start is refused with a console message; the windowed launcher has no console, so it will need to show that refusal some other way (or open the running app, which was decided against for dev runs on 2026-11-13).
  4. Shows the tray icon with Albanian items: **Hap HomeSweeper** (open), **Kontrollo për përditësime** (check for updates) and **Mbyll** (quit; it stops a running scrape cleanly first).
- `python -m Scraper.Server` keeps working for development.

### Updates
**Hosting:** a separate **public GitHub repo, `HomeSweeper-releases`**, holds only GitHub Releases: the installers, the update archives and the manifest, with no source. CI in the private repo publishes there using a fine-grained token stored as a CI secret. The app downloads from the fixed URL `https://github.com/<owner>/HomeSweeper-releases/releases/latest/download/latest.json`, so there is no server to run and no token inside the app. If GitHub ever becomes a problem, any static host (for example Cloudflare R2) works the same way.

**Manifest** (`latest.json`, plus a detached signature in `latest.json.sig`):
```json
{
  "version": "1.3.0",
  "released": "2026-12-01",
  "min_version": "1.0.0",
  "notes_sq": "Çfarë ka të re…",
  "windows": {"url": "…/HomeSweeper-1.3.0-windows.zip", "sha256": "…", "size": 0},
  "macos":   {"url": "…/HomeSweeper-1.3.0-macos.zip",   "sha256": "…", "size": 0}
}
```

**Rules for the updater** (`Scraper/Updater.py` plus a tiny separate helper exe):
- Check at startup, then every 6 h, and whenever the tray item is clicked. Compare versions with `packaging.version.Version`, never as strings.
- **Verify the Ed25519 signature of `latest.json`** with the public key compiled into the app, then verify the **sha256 of the download**. If either check fails, discard the download and log it; never install it. The private key lives only in CI secrets and offline with the owner, never in the repo. Without these checks, the updater is a way to push malware to every agent.
- **Never downgrade.** Ignore a manifest whose version is older than the running one.
- The UI shows a banner such as "Version 1.3.0 is available" with a **Përditëso tani** (update now) button. The update installs on that click, or on quit. **Never update while a scrape is running**: take `SCRAPE_LOCK` (or wait for it) first.
- A running app can't overwrite itself (Windows locks the exe). So the app downloads and unpacks into `update/`, starts the **helper**, and quits. The helper waits for the app to exit, moves the current install to `update/previous/`, moves the new one in, and relaunches. If the new version fails to start (no "started OK" marker within about 60 s), the helper **restores `update/previous/`**.
- Updates replace the whole app folder, which is simple and reliable. No delta patches for now.
- `min_version` is an escape hatch for breaking changes to the updater itself: installs older than it are told to download the installer again instead of auto-updating.

### Code signing (deferred, decided 2026-11-04)
Not doing it for now. **The owner installs the app on every agent's PC personally**, so the first-install warnings are clicked through by them and agents never see them. That only works because of these rules:
- **Windows:** SmartScreen ("Windows protected your PC") only triggers on files carrying the browser's Mark-of-the-Web. On the first install the owner chooses "More info → Run anyway". Updates are downloaded by our own updater with `httpx`, which doesn't add that mark, so they install silently. **Never hand agents an installer link to download in their browser**; that brings the warning back.
- **macOS:** on the first install the owner right-clicks → Open (or runs `xattr -dr com.apple.quarantine /Applications/HomeSweeper.app`). Apple Silicon still requires an **ad-hoc signature** (PyInstaller does this by default; keep it, and re-sign ad-hoc with `codesign -s -` if the bundle is modified after the build). The updater must not set `com.apple.quarantine` on the files it writes.
- If the product ever gets sold to people the owner doesn't install for, signing becomes required: Azure Trusted Signing (or an OV certificate) on Windows, and Apple Developer ID plus notarization on macOS ($99/year). Updates must be signed the same way.

### Versioning and release flow
- **There is one version source: `Scraper/Version.py`**, with `__version__ = "X.Y.Z"` (semver). The UI footer, the updater and the build all read it.
- To release: bump `__version__`, commit, merge to `main`, and push the tag `vX.Y.Z`.
- **GitHub Actions** in the private repo runs on the tag, as a matrix of `windows-latest` and `macos-latest`. It installs pinned deps from `requirements.txt`, runs PyInstaller, signs the build (and notarizes it on macOS), builds the installer or dmg and the update zip, computes the sha256s, writes and signs `latest.json`, and uploads everything to a new release in `HomeSweeper-releases`.
- Pin every dependency to an exact version in `requirements.txt` so builds are reproducible. Upgrade Playwright deliberately, because it changes the Chromium download.
- Scraper fixes (sites change their markup) ship through this same flow, so a fix for a broken scraper reaches every agent within hours.

**Things that will surprise you:**
- **The server needs the `anthropic` package even if the AI is never used** (`Server.py` imports `AI.py` at startup), so a fresh setup must install it (it's in `requirements.txt`; bug B6).
- **State lives in memory:** play/pause, the break, "Jo Listime Agjensie", `RESUME_PAGE`, `AGENCY_UPIDS` and `FAILED_UPIDS` are all in server or module memory. A restart pauses scraping, and the first turn after a restart walks through known pages again before it finds new ones. All of these move to `settings.json` in Phase 4.
- **Saved listings aren't re-scraped**, so price changes on them aren't picked up, and `last_seen` means "last scraped", not "still online".
- **`config.py` in the repo:** `Headless = False` (a visible browser, for debugging) and `Demo_Environment = False` (real turns of 50 per site, since 2026-11-10; set it to `True` for quick 5-per-site tests). The shipped app needs `Demo_Environment = False` and `Headless = True`.

The Engine now prints each turn's time (`Run took N min S s`), so record a real figure in `NOTES.md`.

## Gotchas
- Every scraper keeps its state in module globals. `reset_state()` clears the per-turn state at the start of each turn. `RESUME_PAGE`, `AGENCY_UPIDS`, `FAILED_UPIDS` and `STOP_CHECK` deliberately survive between turns. Two turns must never overlap (the server's `SCRAPE_LOCK` enforces this).
- Scrape state lives in server memory, so restarting the server resets the status pill and pauses scraping. The listings themselves are safe in the DB.
- Playwright headless mode is controlled by `Headless` in `config.py`. It is currently `False` in the repo, so a window shows for debugging; the shipped app always uses `True`. `launch_browser()` and `start_browser()` (copied into every scraper) start the installed Google Chrome, or Playwright's Chromium if there is none, always with `--disable-blink-features=AutomationControlled` (otherwise `navigator.webdriver` is true and tells sites the browser is automated). In headless mode they use Chrome's newer headless mode (real plugins and the real GPU) and swap `HeadlessChrome` for `Chrome` in the user agent, so headless sends the same headers as the visible browser (checked 2026-11-12: User-Agent and `Sec-CH-UA` identical). New scrapers should copy both helpers.
- MerrJep page loads still use a fixed `wait_for_timeout(5000)`. MerrJep listings with no JSON-LD `Product` fail and go into `FAILED_UPIDS`. Gazeta waits for its `__NEXT_DATA__` script instead.
- Scraper errors never cost a turn's listings: a turn that ends early (timeout after 2 tries, blocked, markup changed, browser gone, a bug) still returns what it found, and the reason is in the module's `LAST_TURN` and the log. Only `markup` and `unexpected` failures go into `FAILED_UPIDS`; temporary ones are retried next turn. Scraped text printed through `rich` must be `escape()`d.
- Gazeta's markup is Next.js. CSS class names like `ad-list-card_containerH__cGdas` carry a build hash, so match them with `[class*="ad-list-card_containerH"]`, never the full name. If Gazeta stops returning listings, check the `props.pageProps.getAdsList` path in `__NEXT_DATA__` first (save a page with `Tools.FetchHTML`).
- The server sends `Cache-Control: no-cache` on every response (the `no_stale_ui` middleware). Without it, browsers keep an old `style.css`/`app.js` after a change and new UI elements look unstyled. Keep it; it matters even more once updates ship.
- Saving the Excel file fails if `listings.xlsx` is open in Excel (it warns and doesn't crash).
- Duashpi has a cookie popup whose full-page `#backdrop` blocks every click. If Duashpi clicks start timing out with "intercepts pointer events", check `COOKIE_ACCEPT_SELECTOR` (`#acceptAllButton`) first. Its JSON-LD price is converted to EUR, so never use it for the price.
- `published_date` is text in each site's own format (MerrJep `tet 03 2026`, Gazeta and Duashpi `04/11/2026`) and isn't normalised yet, so never sort by it. The UI's "newest" sort uses `first_seen`. `first_seen`/`last_seen` are UTC.
